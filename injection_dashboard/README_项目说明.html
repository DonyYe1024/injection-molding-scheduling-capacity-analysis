1. 项目概览

项目名称惠州注塑部产能分析看板
用途注塑厂产能分析看板：展示机台产能、模具产能（品种 / GAP）、实单+预算待生产前十占比、原料需求推算、外壳库存水位（饼图）、入库汇总、年度汇总，并支持上传 Excel 实时重算。
技术栈单文件 index.html（原生 HTML + CSS + 原生 JS IIFE）；图表库 ECharts 5.5.0；表格解析库 SheetJS (xlsx) 0.20.3，均通过 CDN 加载（无网时优雅降级提示）。
运行方式双击 index.html 用浏览器打开即可；或本地起静态服务器预览（如 python -m http.server 后访问）。首次加载需联网拉取 CDN 依赖。
数据来源内置数据由源文件《最新排程产能分析-公式模板-最新.xlsm》经 Python 脚本抽取聚合注入；也可在页面上传《工单备料明细 / 最新主排程 / 最新预算》等 Excel 重算覆盖。

2. 文件结构

整个项目核心是 index.html 一个文件，内部结构如下（按出现顺序）：

区域内容与作用
<head> · 两个 CDN script引入 ECharts（图表）与 SheetJS（上传 Excel 解析），各自带 onerror 标记加载失败，供页面顶部横幅降级提示。
<style>全部 CSS：配色变量、布局、卡片/表格/月历/仪表盘/滑动条/下拉等样式。全页样式集中于此，无外部样式表。
第一个 <script>（内嵌数据）声明 4 个常量 EMBEDDED_DATA / EMBEDDED_MAPPINGS / EMBEDDED_ANALYSIS / EMBEDDED_GAP（详见第 3 节）。
<body> 各 section页面骨架：顶部 header（含月历/仪表盘）、上传工具条、KPI 卡片、机台/模具/原料/库存/库存水位饼图/入库/年度汇总等各模块容器（详见第 4 节）。
第二个 <script>（逻辑 IIFE）全部业务逻辑：工具函数、周/日期/农历算法、映射表、全局状态、SheetJS 读取、各表解析器、数据组装、渲染函数、上传重算、事件绑定、启动 init()。对外仅暴露 window.__injectionDebug。
本项目是「数据 + 逻辑 + 视图」三合一单文件。修改任何部分时务必保持「内嵌数据常量」与「逻辑 IIFE」的 const/函数名/元素 id 不变（外部 QA 脚本会按名称引用）。

3. 内置数据说明

4 个常量均由 Python 抽取脚本生成并注入第一个 <script> 块。它们共同构成看板的「离线初始状态」。

3.1 EMBEDDED_DATA

看板主数据，字段结构：

{
  meta: { generatedAt, source, machineGroups },   // 生成时间、源文件名、机台组列表
  machine: {                                       // 机台产能（周轴 + 各组）
    weeks: ["2026WK21", ...],
    groups: { "400T-550T": { label, capTag, real:[...], capLo:[...], capHi:[...] }, ... }
  },
  mold: { weeks:[...], items:[{mold, weeks, hours, qty}] }   // 模具品种数据
}

对应抽取脚本：_extract_data.py。

3.2 EMBEDDED_MAPPINGS

三大映射字典（key 为料号/订单号字符串）：

{
  capacity: { "2090000023": { p:"SK-575外壳", m:"400T-550T", c:"1*1", t:"75", w:"305" }, ... },
              // p=品种, m=机台组, c=穴数, t=周期秒, w=毛重克
  bom:      { 料号: { c:"原料代码", n:"原料名称" }, ... },
  lineDate: { 订单号: "YYYY-MM-DD", ... },
  report:   {}   // 预留占位，暂不参与计算
}

对应抽取脚本：_extract_mappings.py + _patch_mappings.py（补丁/补充映射）。

3.3 EMBEDDED_ANALYSIS

「分析2 / 分析3」结果（机台实单/预算/6天/7天产能 + 前十占比）：

{
  machine: { weeks:[...], groups:{ "400T-550T":{real,cap6,cap7,budget}, ... } },
  top10:   { shell:[{name,pcs,amount,realQty,budgetQty}], acc:[{name,pcs,amount,realQty,budgetQty}] },
  detailDate: "2026-08-28"   // 原始数据1 更新日期
}

对应抽取脚本：_extract_analysis.py。

3.4 EMBEDDED_GAP

GAP 模具产能 + 原料需求 + 外壳库存（明细 / 水位饼图 / 入库汇总 / 年度汇总）数据：

{
  gap: {
    weeks: [...], workdays:[6,6,...],   // 周轴 + 各周工作天数
    molds: [{ mold:"DH001S", cycle:55, sets:3, real:[...], budget:[...] }, ...]
  },
  material: { weeks:[...], items:[{usage,desc,code,name,weekly:[...]}] },  // usage=使用产品(A列)
  stock: [ {code,name,spec}, ... ], stockTotal: 数值,   // 明细来自「原始数据9」塑胶外壳类去重
  stockWaterLevel: { total: 130861, items:[{name,qty,amount,ratio}, ...] },  // 注塑外壳库存水位 5 档
  inbound: { dates:[...30日...], rows:[{group,label,values:[...]}, ...7行] },  // 入库汇总
  annual:  { months:[...12月...], rows:[{group,label,values:[...]}, ...8行] }  // 年度汇总
}

对应抽取脚本：_extract_gap.py。

3.5 如何重新抽取生成

  1. 准备源 Excel《最新排程产能分析-公式模板-最新.xlsm》等原始文件。
  2. 在项目上级目录运行 _extract_data.py、_extract_mappings.py、_extract_analysis.py、_extract_gap.py，再运行 _patch_mappings.py。
  3. 脚本输出即为 4 个 JSON，按原格式替换 index.html 第一个 <script> 块中对应常量的值。

5. 业务规则说明（核心）

5.1 J~W 列公式（前端复现 Excel 公式，computeDetailRows）

上传「工单备料明细」后，逐行补算 Excel 中 J~W 列（有值沿用、无值补算）。列含义（1-based 列号）：

列含义补算规则
B(2)订单号用于查上线日期映射 lineDate
C(3)料号用于查产能参数 capacity、BOM 原料 bom
H(8)需求数量K 列累加基数
I(9)已排产累计数量与 K 比较，判断是否已排完
J(10)订单生产工时（小时）J = 周期S × 待生产L / 3600 / 穴数R，向上取整 2 位
K(11)同料号累计需求数量由 H 按料号累加（第一遍扫描）
L(12)待生产量（扣库存）三段 IF（见下）
N(14)品种缺省取 capacity.p
P(16)周数缺省由上线日期反推（weekFromLineDate）
Q/R/S/T(17~20)机台 / 穴数 / 周期秒 / 毛重克缺省取 capacity.m / .c / .t / .w
U/V(21/22)原料代码 / 原料名称缺省取 bom.c / bom.n
W(23)原料预算KGW = 待生产L × 毛重T / 1000（克→千克）

L 列「扣库存」三段 IF

若 I > K[i]                      → L = 0            （已排产累计超过需求，无待生产）
否则若 C !== prevC（新料号首行）   → L = H            （待生产 = 本行需求数量）
否则（同料号后续行）：
  若 nextSum(K[i+1]) >= K[i] 或 prevL !== 0 → L = H
  否则                                      → L = K[i] - I（剩余缺口）
该函数 computeDetailRows 已经 300 行金标准验证 300/300 一致，逻辑严禁改动，只能加注释。

5.2 机台分组规则（mapMachineGroup）

把机台字符串按吨位关键词归一（顺序敏感）：

含 400 且含 550            → "400T-550T"   （生产外壳）
含 230 且（含 280 或 260）  → "230T-280T"
仅含 260                   → "230T-280T"
含 150 且含 280            → "150T-280T"
仅含 150                   → "150T"
仅含 90                    → "90T"
其他                       → "其他"

5.2b 机台具体化映射（抽取侧 map_machine，改善5）

原始数据4 的 H列【机台】已从笼统表示改为具体吨位（480T/150T/260T/90T/400T/230T/550T/450T/85T/0）。抽取脚本 _extract_mappings.py 的 map_machine() 在写入 capacity 映射前，先把具体吨位映射回网页笼统分组：

85T / 90T              → "90T"
150T                   → "150T"
230T / 260T            → "230T-280T"
400T / 450T / 480T / 550T → "400T-550T"
0 / 空 / #N/A          → 非注塑件，跳过

5.3 模具提取正则（extractMold / moldCoreCode）

extractMold：/DH\d{3}[A-Z]?/i   匹配 "DH" + 3 位数字 + 可选 1 字母（如 DH010、DH001S），从规格/品名中提取
moldCoreCode：去括号注释、按空白分词，保留尺寸词(S/M/L/XL...) 与型号词(字母+数字+字母)，用于预算回退匹配

5.4 周数口径

excelWeekNum：Excel WEEKNUM(return_type=1)，周日为一周首日，1月1日所在周为第1周
normalizeWeek：把 Date / "2026WK34" / "WK34" / 数字34 统一成 "yyyyWKww"；无法识别 → "未排期"
weekFromLineDate：上线日期减 7 天后取 Excel 周（补算 P 列用）

5.5 GAP 产能公式（renderGap）

每周可供产能 = 3600 / 周期秒 × 22小时/天 × 套数 × 工作天数 × 0.85（效率系数）
GAP = 可供产能 - (实单 + 预算)
富余产能弹性 = GAP / 可供产能 × 100%

5.6 仪表盘公式（computeGauge）

月度负荷理论最大值（万PCS） = 1500PCS（单台注塑机日产能均值）× 11（台）× 开机天数 / 10000
负荷% = 待生产外壳数量(万PCS) / 月度负荷理论最大值 × 100

5.7 预算按品名聚合（parseBudget）

预算表从 L 列起「两列一组」（数量/工时）。偶数列 = 工时列，奇数列 = 数量列。

机台级 budget[组][周]         += 工时列值
品名级 budgetByVariety[品名][周] += 工时列值
品名级 budgetQtyByVariety[品名][周] += 数量列值（用于前十按周重算）
budgetVarietyMachine[品名]    = 机台组（用于外壳/配件分类）

5.8 外壳 / 配件分类

机台组为 400T-550T 的品名归入「外壳」，其余归入「配件」（前十占比两张饼图分别展示）。

5.9 农历算法（solarToLunar）

简化公历→农历算法，覆盖 1900-2100 年。数据表 LUNAR_INFO 每年一个十六进制位掩码编码大小月与闰月，仅用于顶部「今天」栏显示农历日期。

7. 如何增删模块

新增一个图表模块（以复制「机台产能」为例）

  1. 加 HTML section：在 <body> 中新增一个 <div class="section" data-module="你的模块">，内含标题、描述、图表容器 <div id="你的Chart" class="chart"></div>（以及需要的筛选控件）。
  2. 加渲染函数：在逻辑 IIFE 里写 buildXxxOption()（构造 option）与 renderXxx()（getChart('你的Chart') + setOption）。
  3. 注册进 renderAll：在 renderAll() 末尾追加 renderXxx();。
  4. （可选）绑定事件：如有交互控件，在 bindEvents() 里加对应监听。
  5. （可选）暴露调试：如需 QA 测试，把 buildXxxOption / renderXxx 挂到 window.__injectionDebug。

删除一个模块

  1. 删除对应 HTML section 块。
  2. 删除/停用其渲染函数，并从 renderAll() 中移除调用。
  3. 从 bindEvents() 移除相关事件监听（若有）。
  4. 从 window.__injectionDebug 移除对应暴露（若有），并确认无 QA 脚本引用。
保持 data-module、元素 id、函数名与现有模块命名一致，避免破坏外部引用。

8. 维护与回滚

重新抽取内置数据

运行上级目录的 _extract_data.py、_extract_mappings.py、_extract_analysis.py、_extract_gap.py 与 _patch_mappings.py，把输出的 JSON 覆盖回 index.html 第一个 <script> 块的对应常量。

回滚

项目内保留备份文件 index_backup_20260830.html。需要回滚时，用备份内容覆盖 index.html 即可。

已知注意事项

  • CDN 依赖（ECharts / SheetJS）需联网加载；离线时图表显示占位、上传解析禁用。
  • 核心函数 computeDetailRows 及一批解析/映射/农历函数为金标准验证过的逻辑，禁止改动行为，只能加注释。
  • KPI 输入、预算日期等会写入 localStorage（key 如 injectionKpi），测试时注意清空以免残留影响。
  • QA 脚本位于 _qa_check/，通过 window.__injectionDebug 在 node vm 桩环境下调用，改动暴露接口前先检查这些脚本的引用。
